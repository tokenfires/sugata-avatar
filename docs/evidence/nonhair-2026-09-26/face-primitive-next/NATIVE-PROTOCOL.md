## Fixed trace and views

Each arm takes 480 native updates at 60 Hz, for eight seconds. Calls occur after the named state is retained:

| Retained step | Action / witness |
| --- | --- |
| 0 | Neutral state, then one scripted bilateral full perceptual blink |
| First actual complete blink before 60 | One declared closure geometry/image witness; all blink weights remain in the per-frame trace |
| 60 | Native `feel('joy')` |
| 175 | Require actual committed smile; retain image |
| 180 | Clear existing named triggers, then native `feel('disliking')` |
| 295 | Require actual committed nose-sneer; retain image |
| 300 | Native `say` with the existing explicit synthetic four-viseme timeline and speech plan |
| 330, 366, 402, 438 | Actual aa / PP / FF / U committed-peak witnesses; aa and U images |
| 480 | Require the native speech promise's `finished` outcome and complete retirement |

The protocol CPU witness calls the actual `Avatar.feel` method and `ExpressionLayer` update; it confirms a smile at 175 and bilateral nose-sneer at 295 without retuning. It also verifies the four predeclared quantized viseme peaks against the actual native schedule/envelope. This is a scheduling fixture, not a rendered/full-Avatar result. Avatar samples the viseme clock before incrementing it, hence the explicit `+1` in peak-step calculation.

Neutral has front, 45° and profile 90° views. The five dynamic plates use the same front view: actual blink, joy, sneer, aa and U. That is eight original native Save image PNGs per arm, without crop or conversion. The clock is explicitly indexed at the existing unique capture epoch; each view gets 64 draw-only settling calls and one native export draw. These draws must preserve the simulation/physical state. The measured startup epoch is retained, not presumed deterministic. No Kitchen expansion is included in this controller.
