## One short native trace per arm

The trace exercises current source owners with the same calls, returned schedules and 60 Hz updates in all four arms. It does not add a per-frame competing morph writer.

- Start with a zero-motion-clock neutral geometry/readback record and the matched initial portrait views.
- Request one bilateral full perceptual blink via the actual `a.layers.blink.blinkNow({unilateral:false, closureAmplitude:1})` (`Blink.js:511`). - Exercise a positive expression with `a.feel('joy')`, using the existing default trigger intensity; record actual smile and brow writers after their normal onset. Its mouthSmile support intersects 63/64 decrease vertices and all 42 increase vertices.
- Clear the prior named trigger explicitly with the existing `a.expression.map.clearTriggers()`, then call `a.feel('disliking')`. This is the real AU9/nose-sneer owner (`ExpressionMap.js:259`), not a guessed “disgust” label. Record transition and actual nonzero `noseSneerLeft/Right`; both overlap all moved tip vertices. A label without the corresponding committed channels is not a successful exercise.
- Use the existing synthetic four-viseme timeline (`aa`, `PP`, `FF`, `U`) from `expression-next/capture-runtime.mjs` through `a.say`, with its exact declared synthetic speech plan. Advance native time before awaiting completion. Record native schedule windows/lead/sample clock, current MotionStack committed values and agreement with every actual carrying mesh. These OVR targets intersect the selected support and exercise mouth opening, closure, labiodental and rounded shapes. Explicitly label synthetic timing/no audio.

The controller should bind concrete step numbers before launch from these source APIs and known schedule durations, retaining onset/peak/release frames and neighboring samples. A CPU scheduling fixture can establish the chosen fixed event times before source freeze. No large emotion/scene/cut cross-product is needed.

**Coverage distinction:** native OVR speech is not proof that raw ARKit `jawOpen` or `mouthPucker` reached a prescribed amplitude. Those raw morphs also overlap the tip support. Before claiming that broader interaction, run separate offline composition checks at each source-declared single-channel diagnostic bound on pristine/−1/+1 (fresh arrays, all other channels zero), including `jawOpen`, `mouthPucker`, `mouthSmileLeft/Right` and `noseSneerLeft/Right`. ## Matched images and stop boundary

Use native complete avatars and original material/light/grade settings. Initial review needs matched **front and three-quarter portraits** for pristine/−1/+1, plus a profile view because tip shape is depth-dependent. Show selected true native smile/sneer/speech peaks in front/three-quarter. A normal clothed wider Studio view establishes the complete-avatar context. If that stage passes, a small fixed Kitchen neutral front/three-quarter comparison checks the unchanged material under the other current room; do not multiply the full dynamic trace by every scene.

Every image has the same declared camera, native renderer epoch, settle/export history and unchanged simulation sample across arms. Extra view draws must not advance motion; preserve numerical state before/after them. Use the real PNG export without crop, resampling or image editing. The prior Wardrobe colour experiment proved that exact cross-owner PNG repetition can fail even on unchanged code after measured startup controls. Therefore this plan must not silently reuse a passed pixel-equality claim: include a pristine/zero image reproducibility control and retain its outcome. If image repetition fails, numerical ownership can still be reported, but appearance attribution stays unqualified until the root chooses and reviews a separate justified method; no guessed tolerance or longer warmup.

Review must inspect nose surface quality and continuity with the surrounding authored normals, nostril/mouth transitions, baked curvature/cavity behavior, actual closure and all visible fitted parts. Neither an image difference nor a nonintersection count proves that an endpoint is attractive or suitable as a default. Stop on an ownership/geometry/cleanup failure, or on a visual defect; preserve that fixed endpoint result. Passing these bounded cases would support a later creation-time primitive proposal, not a continuous slider, all expressions, wider-body fit, representative starter builds or product promotion.
