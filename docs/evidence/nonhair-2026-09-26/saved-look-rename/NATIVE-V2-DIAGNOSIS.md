# Second rejected native run: transport succeeds, blob observation remains incomplete

The v2 production gate stopped before the first Rename group. Its exact controller, network helper/tests, report, manifest and failure screenshot are retained losslessly in `rejected-native-v2/`; the receipt maps them to untouched `captures/saved-look-rename-2026-09-26/native-v2` originals.

All six required original HTTP request bodies matched their pinned source hashes, including bob02 `a666a80777f0b93a824857dc2e2cbffe27cd2c8991a3f4ec8215ebc1d94298bd`, 3,347,176 bytes. The writer's 2 requests and owner's 78 requests all had successful CDP transport completion. No Playwright or CDP loading-failure event was recorded. This does not retrospectively establish the cause of v1's HTTP abort.

All 13 internal blob responses had status 200 and `image/png` MIME. Their content-length headers agree with the expected embedded PNG sizes, but there were no blob dataReceived events and loadingFinished reported encoded length zero. The failed v2 controller did **not** preserve the body string/decoded length/hash/base64 flag returned by getResponseBody before testing its hash. Therefore v2 cannot establish that CDP returned an empty body, altered bytes or another representation. The actual body-witness failures remain unclassified. One native owner was registered before admission, then retired cleanly with no leaked handles and zero tracked renderer memory.

The v3 correction uses a distinct, explicitly named **creation-byte provenance** path. A capture-local observer of the original `URL.createObjectURL` call retains the supplied immutable Blob's intrinsic type, size and SHA-256 using captured native Blob accessors/arrayBuffer and WebCrypto. It preserves the native receiver, all arguments, arity one, synchronous result and thrown error; it never fetches, replaces or revokes a URL. The original descriptor is restored before warmup/UI, and failure cleanup attempts the same owned restoration before independently retiring the avatar. Observer read errors, ownership loss or missing completion are failures. Its asynchronous copy/hash is instrumentation, not a performance measurement.

Each observed creation URL must correspond to a successful same-URL blob request, exact MIME/content-length and completed transport. Its bytes must match a pinned GLB image bufferView, whose original HTTP parent body must also have been observed exactly in the same owner phase. Every creation requires such a response; arbitrary object URLs are not ignored. The CDP return metadata is retained separately. Matching nonempty CDP bytes are cross-checked. An explicitly observed empty CDP return may be labelled as such while the independently measured immutable creation bytes provide provenance; a nonempty mismatch, malformed result or retrieval error stops for diagnosis. All ordinary request failures remain fatal. This is not a claim to recover bytes that CDP did not return.

The source review is supported by 11 network/provenance groups and 6 creation-observer groups. The latter include actual native Node URL/Blob read/restoration, receiver/extra arguments/result preservation, original throw identity, restoration ownership loss, controlled asynchronous read failure, and intrinsic accessor behavior. Node tests do not establish browser behavior. The initial intrinsic-accessor fixture used Node's real URL method, which itself reads overridden Blob properties; it was corrected to use a controlled URL receiver for that specific observer test, while the separate real native test remains.

The original page, asset bytes, production build, native loader and accepted haircut remain unchanged. Native v3 is pending; no Rename acceptance is inferred from these instrument tests.
