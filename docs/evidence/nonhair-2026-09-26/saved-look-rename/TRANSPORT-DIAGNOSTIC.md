# One original-startup transport diagnostic

The rejected v3 packet is in `rejected-native-v3/`. Its source-bound trace identifies one ordinary GET initiated by original FileLoader → GLTFLoader → Avatar.attachHair. It is not an observed duplicate, preload or range consumer. The five CDP data events total exactly 3,347,176 decoded and encoded bytes, matching Content-Length, before `canceled: true` / `ERR_ABORTED`. The server's exact body write finished before the terminal failure. The trace contains the request's initiating stack, not the cancellation stack. There is no admitted whole original HTTP body for that request. V3 also independently records exact creation hashes for all 13 embedded PNGs and explicitly empty CDP blob returns; 11 of these have admitted HTTP parents, while the two groom images do not. None of these facts establishes the cancellation cause or grants an HTTP exception.

`transport-diagnostic.mjs` is a separate capture controller. It leaves native-v3's controller, helpers, report and manifest unchanged. It loads the same original built page under the existing production server/context path, then stops at the page's own normal ready step: clock 0, stack frame 1. It adds no public avatar steps, 64-draw warmup or Rename interactions. The first-frame screenshot is diagnostic, not warmed appearance evidence.

Before page code, `transport-observer.mjs` observes five native method entry points: AbortController.abort, ReadableStream.cancel, ReadableStreamDefaultReader.cancel/read, and Response.arrayBuffer. Descriptor-owned Proxy apply hooks forward the original receiver and every argument, retain native arity/reflection, and return the identical native result or Promise. Original thrown errors propagate unchanged. Auxiliary handlers record native read `done` and byte counts, rejection outcomes, abort/cancel call stacks and a SHA-256 of the ArrayBuffer already produced by the native method. They never refetch, clone/tee a stream, replace a resource, call abort/cancel, modify returned bytes, reset clocks, or await inside the native call chain. There are no signal listeners and no retained stream, reader or controller references: receiver labels use WeakMap keys; observer records contain scalar metadata/stacks. The produced ArrayBuffer is temporarily retained by its hash operation.

The native FileLoader source forwards its Response.arrayBuffer result unchanged through its onLoad callback to GLTFLoader.parse. The diagnostic binds each captured result by its unique full asset digest and actual native FileLoader call stack, since this reconstructed Response has an empty URL. It requires all six required GLBs' exact hashes plus six source-attributed reader groups, each with one successful done result, no rejection and the full asset-size byte-count multiset. This source-forwarded result witness avoids a new GLTFLoader import or parser modification; it is not a second fetch of a known URL.

All observer-owned hash jobs drain outside the original promise chain before exact descriptor restoration. If a method's owner changes, still-owned methods restore while the changed property is preserved and the diagnostic fails. Failure cleanup attempts both observers' retirement and independently retires the actual avatar. Seven CPU groups cover real native read/hash/cancel/abort/restoration, original receiver/arguments/result/Promise identity, original error identity, rejection recording, ownership loss, pre-install descriptor refusal, and finish waiting for an outstanding hash. A first CPU assertion incorrectly counted all Node reader completions as one; Node Response.arrayBuffer itself uses a reader, so the focused check now follows the explicitly created reader's first two calls. No browser claim follows from that host fixture.

This is **instrumented**, not fully passive: auxiliary rejection handlers change unhandled-rejection bookkeeping, and copying/hashing/recording can change scheduling and memory lifetime. The report retains native rejection outcomes directly. An absence of observed JS abort/cancel calls excludes only those observed entry points; browser-internal cancellation need not invoke them and cannot be labelled GC or harmless from absence alone.

`diagnosticCompleted` means the stated observations and cleanup succeeded. `transportAdmitted` separately requires all existing strict request/body/parent checks; a natural loading failure remains recorded and makes it false. `completed` requires both, and `uiQualified` is always false. The ordinary request gate is never waived; the diagnostic does not run the Rename matrix. The root owns any eventual browser launch after independent source review and a fresh manifest/preflight.

On a finish rejection or timeout, the controller separately attempts a bounded read-only report snapshot before rethrowing, preserving active/pending calls and distinct finish/snapshot failures. A ledger request with no terminal event is incomplete observation, not a completed negative witness. Diagnostic completion requires each request to have a finished/admitted body or a recorded matching CDP failed terminal; transport admission still rejects the failed terminal.
