The colour feature is isolated in a worktree. It has not changed the live Wardrobe or its default materials.

What the UI checks establish

Eight focused groups passed with eight matching owner retirements and no browser errors. The checks cover drafts versus applied settings, explicit Apply, partial colours carried between the two existing outfits, clearing custom colours through a whole palette, Original refusal, JSON and named-look restoration, and desktop/mobile controls.

The picker witness uses the real colour input with declared synthetic input/change events. It does not automate the operating-system colour dialog. Native checkbox, hex, keyboard, navigation and file-input paths were checked separately. The last retirement is an explicit pagehide fixture; the preceding seven follow actual navigation.

Why the example images remain illustrations

The front base/custom images are original downloads from the feature’s first rendering run. That run failed its exact returned-base image check. Unchanged old code later failed the same check, and a further control of startup drawing and renderer clock history also failed. Those outcomes do not identify a feature-specific cause, and they do not establish material or default-image equivalence.

The original image bytes are preserved. No crop, recolour, retouch, threshold adjustment or longer warmup has been used to turn a failed comparison into a pass. The prototype remains held while this repeatability issue is unresolved.
