# Independent native startup-control verdict

**Hold the feature's material-image qualification and stop this trial sequence.** The single old-product A/A run with combined startup-draw suppression and early epoch still fails exact returned-PNG equality. No extra retry, longer settling, tolerance change or production/hair change follows from this result.

The rejected report at `captures/wardrobe-colours-2026-09-26/boot-old-repeat-v1/report.json` has SHA-256 `581df0412df3ffbc39f108d6121545d6ab09ef83022c310e7f2787b47e0ca83d`; its reviewed manifest is `e3851be2358f6495bf8a49d7f55caa5ad4a2fc8b2334e47cc4dd0143a3bf21aa`. I independently verified all 1,492 archived non-asset source files, 274 retained response/blob bindings, both image hashes, shared compressed/decoded native state, exact matched reset/settle/export histories, and both clean retirements. The complete state hash remains `cffae4e9bf408a8849ea8314d175978a4bcd91982b93917f8c0d8366ad3a0ea8`.

Both native boot receipts are exactly equal. They record an initially active Stage callback at node frame 1, a cleared callback/stopped RAF with epoch 999999 and zero time, zero Stage draws when the native Avatar factory resolves, then precisely one original Showcase ready draw. That draw changes temporal history from width 1 to 657 and jitter index 0 to 1 while preserving the held clock. All three owned method descriptors are restored before the existing micro-capture protocol. Both pages have one source-bound native HTML transform. No boot/instrument errors, browser errors, native device errors, leaked handles or tracked post-disposal memory remain. These receipts prove the declared Stage.draw control worked; PMREM and other offscreen initialization are explicitly not included in that draw census.

The 657×868 PNGs differ at exactly **one of 570,276 pixels**, coordinate **(351,819)** using zero-based top-left indexing. Base `8c23ad81a02bcccf7e844d84d381c208f6c8df19edca183aa86512e534e351fb` contains RGBA **[73,52,40,255]** there; return `65d1c5a57ed21a25be0411636e04ba95aa40e8cdf19a731e9953b8e7bbf62390` contains **[74,52,40,255]**. This is actual decoded image data, not compression metadata, and remains a failed exact gate. A single pair does not establish a repeatability distribution or permit treating later discrepancies below this amount as acceptable.

I viewed both original images. They appear alike at native display scale, but both have a visibly softer figure than the previous unmodified-startup old-product control, especially around the face, hands and tee edges. Comparing those *different protocols* numerically yields 219,715 changed pixels and a maximum channel difference of 137/255. This cross-protocol comparison is descriptive, not an acceptance test or proof of a particular cause. It shows why near-equality within the new pair cannot by itself qualify the intervention as an innocuous capture fix. The recorded geometry remains exact while rendered output changes materially.

The result does not support “startup hold solved the cause.” It shows that the combined intervention worked as instrumented and did not restore the chosen exact-image criterion. The earlier unchanged-product rejection already demonstrated that the failure can occur without colour code. The independent UI packet remains accepted for its eight bounded interaction/layout groups; the twelve-view colour rendering experiment remains incomplete and held.

Two concrete alternatives for a later, separately reviewed diagnosis are:

1. **Locate the first diverging render boundary without changing shader parameters.** `GBuffer.js` retains actual output attachments; `TRAAPost.js` exposes the temporal node while `resetFrameEpoch()` resets only jitter and history size, and `Grade.js` subsequently composes/sharpens/grains the image. A bounded copy/readback of existing scene output, temporal resolve/history and final output after the already scheduled draw could distinguish an upstream difference from temporal or final encoding divergence. It must add no new scene draw, preserve the native ordering and retain exact formats/bytes. This is more direct but needs carefully reviewed asynchronous readback ownership and cannot infer cause merely from a first differing boundary.
2. **Audit non-beauty initialization and compiled inputs.** `Avatar.build()` calls `InteriorEnvironment.attachTo()`, whose `bake()` and solar bake use `PMREMGenerator.fromScene()` outside the Stage.draw census. Record actual generated environment-target bytes, bake/light inputs and relevant compiled shader/pipeline identities under the two declared protocols before inferring they are equivalent. This covers an acknowledged blind spot while leaving all accepted assets/defaults untouched, but is broader and could produce a large amount of equal data without localizing the one-pixel residual.

Neither option is an instruction to launch now. The current stop is appropriate; preserve the rejected native receipts and keep the isolated feature unpromoted while choosing future work deliberately.
