I viewed both original images: the full outfit and composition appear consistent at native scale, while numerical comparison proves the sparse differences.

This establishes that the strict fresh-page image failure can occur **without the custom-colour implementation** under this capture protocol. It refutes attributing that failure solely to the new colour code. It does not prove the feature has no independent regression, identify the underlying renderer mechanism, retroactively pass either packet, or qualify the nine unexecuted feature views.

The existing comment at `packages/testbed/src/alive.js` around line 3000 describes a measured historical async wardrobe-startup leak in a different page: a running Stage rendered partially loaded meshes before capture, and resetting frame/jitter/history did not reset every mesh-specific renderer input. The current Stage also starts its loop during initialization. This is a relevant source hypothesis, **not a causal proof for current Showcase**. An appropriate next diagnostic would record the actual pre-readiness draws and relevant temporal/material state without changing the native work, followed by a separately reviewed intervention only if the witness supports it. Holding integration while completing independent UI checks is the lower-cost alternative; it preserves the visual gap explicitly. No further retry, hair change or threshold change is implied.
