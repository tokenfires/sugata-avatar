# Identity-aware extension of the existing blink instrument

The first pilot's independent ray oracle agrees at every sampled point for its four
configurations. Those cases remain an **opaque-globe, morph-coefficient** study. The
current runtime calibration and the existing `ocular.selftest.mjs` geometry instrument
must own the next comparison.

The proposed second CPU protocol is fixed before looking at its output:

1. Bind the same exact g050 source GLB and identity/map data, plus `Blink.js`, its exported
   `BLINK_CONSTANTS.FULL_CLOSURE_MORPH_WEIGHT`, and the existing ocular instrument source.
   Keep the first pilot source/report/masks intact.
2. Evaluate the body in its source rest frame. Keep the current eye meshes unchanged.
   This is intentionally a body-only identity diagnostic; fitted-proxy integration is
   still outside it. All body/globe/cornea mesh transforms must match the asserted source
   frame. No hair, material, mask, lighting, skeleton or asset change.
3. Use exactly two identity states: no target, and the historical named
   `eyes/eye-height2-decr-incr: 1` case. Evaluate each at blink coefficient 0 and at the
   isolated native Blink full-closure coefficient, currently 0.752. This is not the full
   composed native-frame output. Do not search amplitudes or
   another identity if the historical claim does not reproduce.
4. Intersect actual triangles as before, but report **two separate surfaces**: opaque
   globe visibility and front-of-skin corneal-shell geometry. A transmissive cornea is not
   opaque colour, so the latter is a geometric exposure measurement. Match the actual
   GLB sidedness and retain a documented comparison with the older instrument's
   two-sided rasterization if they differ.
5. Retain the finite 0.1 mm pitch and derive bounds from the union of both eye surfaces,
   verifying every globe/cornea vertex is contained. Report exact bounds, ray positions, per-eye
   masks, sampled areas and column spans. There is no inferred continuous zero-gap or
   <0.2 mm guarantee. Measure both sides; symmetry is an observation to check.
6. Independently compare every sample against a 3D ray/triangle oracle. Include
   hand-solvable occlusion controls in that validation: a front cover hides the target,
   a rear wall does not, a known open window exposes it, and reversed winding follows
   the declared side convention. Do not convert an edge-rounding mismatch into a passed
   visibility claim by adding an unreviewed tolerance.

If the named identity exposes eye geometry at the actual native blink coefficient,
record that red geometry witness. If it does not, preserve the non-reproduction and
investigate the historical mean-displacement claim without forcing agreement. Either
result still needs an actual native skin/eye comparison before an appearance claim.
No corrective, altered blink calibration, accepted identity range, PUNCHLIST completion
or product/API integration is authorized by this protocol itself.

## First execution, independent review pending

`aperture-calibrated.mjs` executed only the four declared configurations, with a union-bounded
908 × 319 grid and the coefficient extracted from the current pinned `Blink.js`. Report
`captures/identity-closure-2026-09-26/calibrated-cpu-v1/report.json` has SHA256
`1a2329532bebb49efb98835e04eec561bf56188c4f240ed505edeb51010f54c4`.

At coefficient 0.752, the unmodified figure has zero sampled exposure of either surface.
The body-only eye-height2 +1 case has 2,323 exposed opaque-globe samples per side
(23.23 mm²) and 2,397 exposed corneal-shell samples per side (23.97 mm²). Both have a
maximum sampled column span of 2.1 mm. The asset-sided and both-windings masks agree in
all four cases. The open target case's eleven-sample left/right difference remains in
the report; symmetry was not forced.

These are candidate red/green geometric witnesses, pending independent oracle and
hand-solvable-control checks. They do not establish correct proxy refitting, appearance,
continuous gap bounds or an appropriate corrective. `plot_masks.py` produces the labelled
numeric overview directly from verified masks; root inspected it. Its image is a scientific
CPU plot, not a native avatar screenshot.
