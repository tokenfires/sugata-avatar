# Startup-only warning attribution

Smoke v2 reached the original default Wardrobe avatar on a nonfallback Apple/Metal adapter with `timestamp-query`, but stopped before the first measured update. Four warnings had been classified as fatal errors: one Figure missing-jaw/eye-bone diagnostic, one native zero-index draw warning, and two Three inline-Fn return warnings. There is no timing result. The exact v2 report, controller and runtime are preserved under `rejected-smoke-v2/`.

The actual native teardown disposed the avatar, reported no leaked handles and returned renderer tracked memory to zero. The old instrument nevertheless called cleanup incomplete because neither timestamp pool existed yet. Pools are created on first observed timestamped pass. The corrected cleanup predicate admits absent pools only when the runtime proves `counter === 0`, `lastAttempt === null` and `records.length === 0`; once any measured step is attempted, both pools must exist, be idle and dispose. An abort cleanup receipt never substitutes for per-update accounting, and cleanup drains cannot launder a failed measurement.

The Figure warning is emitted by `Figure.js:422–426` after computing unmapped humanoid bones. The accepted g050 rig has no jaw/eye bones and the diagnostic specifies the existing morph fallback. The current wardrobe census has fully hidden foundation briefs with zero draw range; native `WebGPUBackend._draw` passes its index count to `drawIndexed` without dropping zero. These source observations are consistent with the first two warnings, but the diagnostic will retain the actual zero-index draw's mesh, ancestry, material, draw parameters and call stack before attributing the native warning.

The two TSL messages come from `ConditionalNode.generate` when an inline conditional branch yields a return value with no function layout. Native Three then comments out that return. The messages alone do not reveal the originating shader, and are not presumed harmless. The diagnostic turns on native `Node.captureStackTrace` only during unchanged original page initialization. Native Three formats its captured creation stack into the original warning string. The corrected observer leaves all shader-node methods untouched and retains that raw warning plus the `console.warn` emission stack. Only `console.warn` and native `_draw` are wrapped, with their exact function-length descriptors preserved. All method descriptors and the debug flag are restored before readiness; raw browser warnings additionally carry phase and console location.

This run has its own manifest kind and CLI. It performs only the original page's startup (including its original zero-delta frame), takes a readiness screenshot, then retires. It calls no instrumented fixed-step update. A completed diagnostic means evidence collection and teardown completed; `measurementCompleted` remains false. All warnings remain fatal for a timing smoke until exact source/count/phase admission is independently reviewed. GPU errors, unknown warnings and timestamp overflow never receive a general exception.

CPU checks use the actual Three classes to verify native return/error forwarding, raw creation/emission traces, and exact descriptor restoration. Separate hostile cleanup cases reject absent pools after measurement starts, pending mapping, allocated queries and contradictory ownership. A fourth group executes actual native `_draw` against a modeled encoder and verifies the zero-count indexed submission and native stats are forwarded unchanged. Seven corrected observer groups additionally execute actual `Node.build` dispatch against modeled builder data, demonstrate the exact rejected-v3 arity/cache error, and reject a later console owner without overwriting it. Three CPU HTTP groups prove capture-only tag replacement and native Vite client injection. They do not establish actual warning sources or native timestamp completeness.

## Rejected v3 and corrected bootstrap

Startup v3 failed for instrument reasons and has no accepted diagnostic or timing result. The removed `ConditionalNode.generate(...args)` wrapper had length0; native `Node.build` selects generation/caching behavior via `generate.length < 2`. It therefore stopped passing the requested output type and introduced invalid WGSL `void` declarations. Those shader errors are not attributed to the product. Direct-call tests had missed the reflective dispatch; the new actual-Node.build regression proves the old error and unchanged current behavior. The exact v3 report/controller/runtime/helper/tests are retained under `rejected-startup-v3/`.

V3 also intercepted the raw HTML response, bypassing Vite's normal initial client injection. The newly imported CSS loaded that client later, displacing `console.warn`; exact restoration correctly rejected the competing owner. A WebSocket local-network-access error was also retained. The successor uses a capture-local Vite `transformIndexHtml` pre-hook to defer only the original main module, while serving the real network HTML response with native client injection. An explicit completed import of the same `/@vite/client` precedes all console observation. No browser permission, launcher flag, product file or error policy changes; any remaining client/WebSocket failure still stops before avatar startup. The HTTP CPU selftest uses a separate temporary optimizer cache and closes its server. Startup-v4 subsequently confirmed this corrected native HTTP path with zero browser/network errors; see `native-startup-v4/INTERPRETATION.md`.

The rejected v3 nevertheless contains a narrow local draw witness: native `_draw` received `garment_foundation_briefs`, indexCount37494 and drawRange0 with vertexCount0/instanceCount1 in both shadow and beauty contexts. This is evidence of those received calls only. It cannot establish ordinary startup pass counts or qualify all original warnings while the shader observer was corrupting another path.

## Measured successor admission

Startup-v4 is sealed as diagnostic-only evidence. The exact source/count/phase policy now lives in `startup-policy.mjs`; its retained fixture is limited to default Wardrobe/casual/ecru/bob02. Every raw warning remains visible. New/late warnings still reject the run. Eight normal warmup steps and the final twentieth step must prove current native workload/history/card readiness before the smoke can complete. Seven focused CPU groups exercise retained diagnostics and explicitly modeled new live/warm fields; native timing and those new live receipts remain pending. See `native-startup-v4/INTERPRETATION.md` for the unwarmed initial-plate limitation.
