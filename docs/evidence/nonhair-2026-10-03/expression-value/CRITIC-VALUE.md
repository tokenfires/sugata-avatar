# Expression value: refuse a new control or facial recipe now

Decision: no concrete expression implementation is admitted by this value review. Current source proves existing capabilities, but the retained current face witnesses do not establish a missing user action or a new curated facial target. This is a refusal of this proposed slice, not a reduction of the expression/AAA roadmap.

## Source and actual frame witnesses

- `packages/testbed/src/showcase.html:65` already exposes **Look toward me**, **Look with a smile**, and **Release**. `showcase.js:164–170,443–450` guards these choices and reports their phases. `AttentionAction.js:117–160,175–198` accepts neutral/soft-smile only, owns a finite envelope, and releases explicitly. Neither action is missing.
- `portrait.html:74–84` already exposes **At ease**, **Warm**, **Curious**, **Determined**, and **Ease to neutral**. `portrait.js:119–140` drives literal PAD targets through `Avatar.feel`, including Warm `{pleasure:.7, arousal:.25, dominance:.35}` and the neutral target `{0,0,0}`. Wardrobe's header already links to that Portrait study (`showcase.html:23`). A new preset inventory or another discoverability guide would duplicate existing work.
- `Avatar.js:1749–1812` supports imperative affect input; `ExpressionLayer.js` and its paired PostureLayer make this a dynamic face-and-body state, not a static morph photograph. `showcase-settings.mjs:19–51` faithfully reconstructs its supported static look fields and rejects unsupported fields. `showcase-presets.mjs:42–55,60–106` does not export a current affect state. A reopenable facial presentation would therefore need an explicitly new runtime/settings ownership contract; it cannot honestly be presented as an already supported recipe option.
- I previously actually viewed the archived current originals `listener-view/archive/capture/baseline.png`, `hold-late.png`, and `return.png`. The baseline has a sideward pose with one eye obscured by hair; hold-late makes both eyes visible; return stays more frontal. They support the delivered brief attention-view guide, not a new affect design or a defective neutral face. The current whole-front originals were also inspected, but the modelling proposal's open eyes are geometry witnesses rather than expression evidence.
- `PRODUCT-ROADMAP.md:118` explicitly preserves integrated attention/smile ownership and asks for a proved need before more cue infrastructure. The September26 `expression-next/DECISION.md` already distinguishes engagement from determination and retains production behavior. Repeating those still treatments under a new name would not settle a new question.

## Two alternatives and tradeoffs

A. Keep Wardrobe's current neutral/soft-smile attention controls and use the already exposed Portrait PAD controls for the existing expression study. This avoids duplicate state ownership and preserves accepted behavior, but Portrait is a separate study and does not preserve the customized clothing recipe.

B. If a user-facing need for **clothed affect inspection** is independently established, a future slice could expose a strictly limited existing PAD choice in Wardrobe with explicit neutral release and transient-view wording. It would preserve clothing during that inspection, but requires guards, face/posture/attention composition review and a declared visual objective; it must not silently promise saved emotion, readable warmth or natural listening. The absence of those buttons alone is insufficient admission evidence today.

The smallest decision-changing question would be whether a specifically intended clothed facial presentation improves a named current visual reading compared with neutral while preserving the existing owners. No new target or evidence of that need was supplied here, and the broader expression inventory already exists. Stop this value step now: no new cue, expression schema, facial recipe, capture or guide. Continue a separately witnessed character/wardrobe finish decision rather than manufacture an expression feature gap.
