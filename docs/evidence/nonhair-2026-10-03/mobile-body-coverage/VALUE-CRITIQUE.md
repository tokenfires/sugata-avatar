## One finite method

Use only the exact previous mobile casual/neutral/body configuration and390×844 viewport as the initial diagnostic. Preserve current sources/assets; this is not a sweep over outfits, poses, viewports or camera candidates. Record actual resolved configuration, attached-mesh inventory, active triangle IDs/counts, matrices, morphs, bind/skeleton state, camera coordinate system/projection, CSS canvas rectangle and actual overlay rectangles. Separate body, garments/shoes and any excluded dynamic-hair support explicitly; the result is whole body/clothing coverage, not a new full-hair-envelope qualification.

Root may produce one paused native packet containing a page original and a canvas-only original at that same state/canvas size, with the controls still present in the page. Retain state equality around both images. The canvas-only image exposes the native image beneath controls without a layout change or alternate camera. No GPU compute/contact kernel, asset change, history/epoch search or hair retune. Record nominal versus any actual render-jitter projection convention; do not claim subpixel raster coincidence from an unjittered camera.

Project the currently drawn triangles with finite homogeneous/depth checks, respecting near-plane clipping rather than dividing points with invalid/negativew. Report per-mesh signed distances to all four canvas edges and witnesses for out-of-frustum support. Report projected triangle overlap with actual controls/heading rectangles; their bounding rectangles are conservative annotation extents, not an opaque-pixel mask. Preserve exact source triangle/vertex examples and CSS↔canvas mapping. Mere overlapping bounding boxes should not be called intersecting triangle support.

The explicit diagnostic completeness contract is: every active body/clothing triangle's projected support lies within the canvas and outside the declared UI annotation regions. Use zero separation for this baseline and report distances; a later desired composition gutter must be separately authored before fitting. A conservative rectangle failure means the contract fails, not that every affected pixel is physically hidden. This diagnostic contract tests complete geometric support, not appearance or camera aesthetics.

Classify outcomes narrowly:

- **Frustum support loss:** named body/garment triangles cross the actual canvas/depth bounds; corroborate the missing lower-body region in the native canvas original. This can admit a later camera/framing question, without selecting its solution.
- **Projected overlay overlap:** support lies in the canvas but intersects a UI region. A canvas-only original showing the corresponding feet/shoes while the page hides them is the useful visible witness for layout/usable-area work.
- **Both:** retain distinct clipping and overlap witnesses; do not infer both from the current page alone.
- **Unresolved:** missing mesh ownership, invalid projection, incongruent states, shader support disagreement, or no native correspondence stops before a candidate. CPU overlap alone remains support evidence.

The smallest useful output is the coverage contract, per-mesh classifications/witnesses, two actual originals and one comparison report. Independent arithmetic and actual-image critique must fit inside the same15-minute slice. Stop after this single packet or any structural/ownership/state failure; preserve partial receipts and close without changing camera/layout. No additional positive-control viewport is necessary to answer this exact mobile case.
