## Editable source and lock arrangement

The proposed source is `tools/ember-hair/ember-waves-v001.json`: an ordinary versioned text document containing named guide control points in the frozen figure's metre coordinate system, width and roll controls, scalp anchor, layer, atlas strip and semantic lock group. Each guide is individually authored with 8–12 explicit points; no random placement, curl slider, hemisphere generator or global sine displacement creates the hairstyle. The compiler only interpolates those authored curves and makes their ribbons. Future changes edit a named lock, not a hidden seed or an entire character representation.

Initial allocation is40 guide paths, three narrow overlapping ribbons per path, with a hard ceiling of48 guides and192 ribbons. These are construction limits, not a density or quality pass:

| Named family | Guides | Authored responsibility |
| --- | ---: | --- |
| `crown-sweep-01..08` | 8 | Start either side of a narrow off-centre part; rise from the scalp then sweep toward the heavier picture-left side. Inner roots overlap underneath the next row. Peak lift initially20–35mm above the measured crown; no smooth shell under them. |
| `temple-heavy-01..04`, `temple-light-01..04` | 8 | Continue crown flow around each temple. Heavy side bends outward then returns beside the cheek; lighter side sweeps back above the ear. Preserve the brows and both eye openings. |
| `side-heavy-01..06`, `side-light-01..06` | 12 | Provide the recognizable separated loose waves. Individually placed bend/return/bend controls,10–25mm lateral excursions over70–110mm vertical spans; neighboring phases and endpoints differ. Broad S bends with modest roll, not complete spirals. |
| `occipital-01..08` | 8 | Cover rear skull with overlapping actual strand-bearing locks, continuing into the back silhouette. Stagger roots and overlap laterally; do not merely place decorative locks over a cap. |
| `nape-01..04` | 4 | Close the rear/side transition beneath the outer locks; shorter endpoints at the shoulder region. These are visibly textured, shaped cards, not opaque filler. |

Widths start around8–18mm per ribbon, narrowed toward broken/staggered tips. Three ribbons in a lock have separately recorded offsets/roll/width profiles within a2–5mm depth band; they must not form a flattened sheet or identical stacked copies. Outer locks have explicitly authored front/back depth. A parallel-transport frame along each curve avoids twist flips; authored roll then controls each lock's visible broad face. A three-vertex cross section gives shallow camber, without closed tubes. Sampling is32 longitudinal segments, with no more than40 if the chord-error check requires it. Set the maximum curve-to-chord deviation at segment midpoints to0.35mm; evaluate it once at32 and, only if needed,40 segments inside the same compilation. Failure at40 stops rather than increasing the budget or silently flattening the wave. A near-zero tangent or unresolved frame flip stops the build.

The JSON preserves the human-readable intent for every guide, plus the precise source hashes and resolved triangle/barycentric root. The generated indexed mesh and a guide-to-vertex mapping are separate outputs. No proprietary authoring application, download or paid dependency is required. An editable `.blend` is not necessary for this candidate; the explicit curves, attributes and compiled mesh remain independently recoverable.

## Actual attachment and coverage

Before compilation, each authored root seed must resolve once onto an explicitly allowed scalp triangle: a top/rear/temple region with outward-facing normal, excluding forehead below the intended hairline, facial features and ears. Store triangle vertex IDs, barycentrics, normal and a0.3–0.8mm outward root offset. Resolve a separate anchor for each ribbon and each vertex of its root cross section, not just the guide centre; store the resulting anchors in the source mapping. This makes the root row conform to the actual curved scalp before it opens into the authored lock. Interpolate the root's existing skin weights; all accepted root triangles must be at least.999 head-weighted at all corners. No nearest-point result on an ear or eyebrow is accepted as a root. Generated ribbon surfaces, including all three cross-section vertices and triangle interiors, may not penetrate the skull/face/neck; a centre-line-only test is insufficient. Use bounded broad-phase cells followed by signed nearest-surface and triangle-crossing tests for candidate pairs. Test both bind and the prescribed head turn, including the shoulder region. Only the root row has its explicitly recorded0.3–0.8mm outward placement; this is not permission for inward penetration.

The proposed first mesh is rigidly head-attached, using the actual bone rest matrix, not an estimated pivot. At bind pose, transform authored figure-space points into head-local space using the inverse of the head-to-figure matrix, then parent the mesh to the real head bone. Verify the reconstructed bind positions and root anchors numerically. Residual over0.5mm after accounting for that offset blocks the candidate. Do not count the intentional offset itself as drift.

Coverage comes from staggered overlapping inner and outer guide rows over the whole crown, temples, occiput and nape. Inner rows sit2–5mm off the scalp and follow the same flowing direction; outer rows supply lift and wavy volume. Preserve a narrow, intentional part rather than hiding every scalp pixel. Roots overlap inside the neighboring lock's coverage instead of exposing flat card starts. The ordinary skin underneath stays unchanged. Do not add an opaque skull shell, recolour the skin as a rescue, or infer coverage from ribbon count. The first actual front/angle/rear views decide whether holes, flat slabs or a helmet remain.
