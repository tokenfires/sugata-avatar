# Fixed implementation and workload — inert, unadmitted

The unchanged October10 CONTRACT.json is normative. These programmes are a proposed implementation, not a successful source, field, mesh or appearance result. No programme may run without a new complete independent source/workload review, root verification and a finite one-shot admission. AST parsing is the only preparation-time code evaluation permitted.

The implementation uses only Python standard libraries and Blender5.2.2's documented mathutils.bvhtree.BVHTree API. It creates no Blender scene, object, material, renderer, dependency graph or GPU work. No older builder, source geometry, mask, observer or renderer is imported. All four arrays and seven source-file hashes remain literal. A new standard-library NPY reader admits exactly the four pinned nonobject members; unused payloads stay opaque.

The exact method is all original source triangles, formal closed-chain prerequisites, reported native nearest/range policy, exact all-hit XYZ classification, all seven sampled inequalities, shared positive tetrahedra, exact rational convex clipping, canonical support/active-inequality identity, complete polygon labels, boundary topology, plane association and all finishing-parent duties. There is no reduced-grid, nearest fallback, perturbation, tolerance weld or shape/control search. A numerical or native failure stops with a recorded stage and reason. An incomplete diagnostic output cannot be a complete pass.

For all-hit enumeration only, each original triangle's projected axis-aligned bounding box restricts which fixed q32 columns it can intersect. This filter is conservative: closed triangle projected coordinates are convex combinations of its three projected vertices, hence lie inside both closed min/max coordinate intervals; binary-rational comparisons and bisect on the unchanged axis stations include both endpoints. Every candidate then receives the exact projected barycentric test. Degenerate projections use exact projected segment membership; any hit marks that complete column ambiguous. There is no directional/seed change, nearest ray, mask or missed-hit fallback. Counts and caps apply to this enumeration and to the unchanged full grid/tetrahedra.

All finite sampled coefficients become exact Fractions using as_integer_ratio. Convex polygons are clipped by exact segment/plane ratios. New cut faces are cycles in the intersection adjacency graph; exact gradient orientation establishes outward order. Positive-area coincident owners, non-simple/rank/ordering failures refuse. Global identities preserve exact support weights, all active cut IDs, world coordinates and complete labels. Internal lattice faces require exactly two opposite cyclic owners. Every surviving polygon is labelled before canonical triangulation.

Source eligibility and numerical representation eligibility are separate output states. Finishing parents can HOLD independently; a complete representation PASS requires all topology/plane/parent gates. Physical collision, coverage, simple-solid truth, pose/rig/morph and appearance remain UNKNOWN even then. **This first proposed job is explicitly a no-image technical-output scope.** It may only produce source/field/mesh/parent evidence. A first source-mesh inspection image needs a separately reviewed and admitted image programme and budget after successful numerical collection; no appearance credit or promotion is admitted here. This scope choice itself is part of the complete source gate, before any trial.

Proposed fixed workload: one Blender CPU/native worker, 900s worker wall, 1200s entire supervisor wall, 4GiB sampled aggregate owned-process RSS, 2GiB sampled aggregate output bytes, 256MiB hard per-file limit, 900/905s hard worker CPU soft/hard limit. Poll interval0.25s; sampled limits can overshoot and do not guarantee allocation headroom. No memory-pressure or free-memory claim. Work caps: 4,000,000 projected candidate tests; 1,000,000 exact proper ray hits; 8,000,000 native range records; 1,000,000 canonical vertices; 2,000,000 surviving-or-pending facets; 4,000,000 output triangles. Every cap stops/refuses, never drops records into a PASS. Fixed full counts remain1,901,380nodes and11,099,520tetrahedra. All required metric/ray records must be retained within these limits; output-budget exhaustion is a refusal.

The supervisor uses exclusive one-shot ownership, a new session/process group, pinned programmes/runtime/input bytes, and a future root-signed admission file binding every programme and input with a short invocation window. It records actual PID/PGID/birth identity, command, wall clock, logs, stages, sampled resource observations and positive wait/reap/remaining-process checks. TERM/HUP/INT and timeout request a bounded TERM then KILL of only identity-confirmed owned processes. Unknown process identity or cleanup failure is an explicit collection failure, never permission to signal an unrelated/reused PID. Unexpected supervisor death is not proof of worker cleanup; durable live-owner metadata must be reconciled before any later job. No retry or automatic new directory/job.

No execution is reserved. Source preparation cutoff13:15UTC, independent/root review checkpoint13:30UTC. The exact source handoff must disclose gaps or refusal, preserve all unrun code, and retain constructor HOLD if anything remains unowned. Full roadmap and all previous method closures remain unchanged.

Implementation detail for review: full metric records are losslessly serialized as gzip JSONL in fixed65,536-record shards; ray/vertex/facet/triangle records use gzip JSONL and the export also includes OBJ. Compression changes storage only, never distances, rational identities, source membership or qualification. Each shard retains exact JSON finite scalar representations and rational numerator/denominator pairs. Compression/record caps may still refuse; no output-feasibility claim. The total20minute clock is a stop threshold with bounded shutdown/collection allowed to follow it, not a hard kernel wall cap. Worker wall is a0.25s-polled threshold, worker CPU and per-file sizes are kernel limits once worker Python starts; Blender startup precedes those CPU/file limits. The20minute threshold also includes admission pin hashing, with chunk-level deadline checks. A live unreaped direct Popen child can receive TERM/KILL even if the first process-inventory read failed; its unreaped live child identity prevents PID reuse. Other processes require recorded birth/group/command identity. Absent/split/reparented/escaped descendants are not universal cleanup proof; unexpected group/identity/collection conditions fail the result and require reconciliation, never automatic retry.
