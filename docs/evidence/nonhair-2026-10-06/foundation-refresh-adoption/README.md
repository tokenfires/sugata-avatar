# Foundation switch repair

Changing the foundation preference previously saved the new choice and then asked the wardrobe to retain the old foundation IDs. The two real-source counterexamples show that this request refuses before loading the replacement. [Original proof](../foundation-switch-probe/ROOT-ACTUAL-CLOSE.json).

The locally adopted repair adds `WardrobeAgency.refreshFoundation({ by: 'user' })` and routes both foundation buttons and the public `prefer` handle through the same operation. It applies the selected foundation while retaining the current outer garments. A stored pin keeps its own outer garments, including when dormant or already different from current wear.

One isolated run passed twelve cases. Root checked every raw record and the predeclared observer. The independent critic separately reparsed the results and agreed. Root froze all 28 candidate payloads and copied the three qualified files; their bytes match the tested source projections. [Actual review](../foundation-refresh-candidate/ACTUAL-CRITIC.md), [root qualification](../foundation-refresh-candidate/ROOT-ACTUAL-CLOSE.json), [exact delivery](ADOPTION.json).

The cases cover torso and hips selection, repeated selection, active and dormant pins, restart/wake/restore, existing pin drift, pending AI suggestions and genuine history, invalid choices, load refusal, supersession, delayed result delivery, disposal and a storage failure after application. A saved choice can remain after a load refusal. A storage error after application can reject after the outfit changes; rollback is not promised.

The delivery is exactly the Agency module, the testbed caller module and the new regression file. [Exact inputs and destinations](PLAN.json). Neither the browser controls nor personal storage ran in this CPU trial. Physical coverage, fit, appearance and moving-avatar quality remain open. Accepted visual assets and the full character roadmap are preserved.
