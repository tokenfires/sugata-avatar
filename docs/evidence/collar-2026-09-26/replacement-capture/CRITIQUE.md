# Independent capture-adapter review — 2026-09-26

**Verdict: the version-2 adapter is ready for the bounded sixteen-run comparison.** Its CPU contract and native vest smoke support the capture mechanism. Completion and qualification of the full comparison remain separate.

Reviewer: independent critic agent `/root/critic`. I reviewed `collar_replacement_capture.mjs`, `collar_replacement_manifest.mjs`, the six-group selftest, the imported browser helper, the version-2 manifest and native vest smoke report. I reran all six CPU groups and validated the actual manifest against all 355 current source/asset/instrument entries. I independently verified the vest smoke's 121 PNG and 15 compressed geometry hashes and inspected its ordinary step-0 image. I did not run a browser/GPU job or edit runtime/asset sources.

The contract gives each comparison an explicit garment role, hair, sequence and actually worn foundation. Mandatory installed/frozen bytes are pinned, a trial must be distinct, and the manifest fixes camera, seed and schedules. Validation precedes browser creation. Wrong identities, source drift, malformed schedules, missing native meshes, mismatched selected foundation topology, response-byte drift, incomplete cadence and late browser/disposal errors leave the run incomplete. Source checks surround each run, and failed evidence is retained. This is meaningful failure behavior rather than an exit-zero assumption.

The browser uses the native loader and checks returned garment/foundation response hashes. The vest run initially loads the page's default bra, then selects vest through the ordinary preference/dress APIs before the capture clock starts; its final worn set correctly contains vest, briefs, outer and shoes, with no worn bra. A loaded bra response is therefore expected and must not be mistaken for a vest fixture failure. The selected vest has 15,455 vertices and 28,832 full source triangles. The smoke records exactly 121 images, 15 snapshots, Look at step 60, explicit Release at 240, a six-second final clock, no errors and zero remaining renderer allocations/Avatar handles. `qualificationCaptureComplete:false` correctly preserves its limited meaning. The older bra smoke is version 1 and supports that earlier mechanism, not all version-2 behavior.

The cadence and command boundary are coherent: 60 Hz native updates, 20 Hz images, regular discrete geometry plus the actual returned expressive peak neighborhoods. Commands follow the named rendered step, so same-step telemetry may describe the new command while geometry still depicts the preceding state. This is documented rather than silently relabelled. Images and snapshots use the real skinned/rendered pose, while the saved mesh positions are CPU-skinned world positions; they are not a claim of GPU-deformed vertex readback or unsampled continuous clearance.

Paired comparisons use the right separation. Garment-role pairs within a foundation require matching sampled native physical, affect, attention and command state. Bra/vest comparisons deliberately exclude foundation geometry and visibility/mask differences. They compare body/outer bones, morphs, clocks and posed-coordinate digests, and report `separate-actual-pose-families` if those differ. Such a result must remain distinct actual evidence; it must not be normalized away or treated as interchangeable poses. No full-matrix comparison result was available when this review was written.

The ordinary vest smoke clearly preserves the open, jagged collar defect. That makes it a useful capture witness, not an appearance or fit pass. Hair remains unchanged and deferred. Current optional-trial capture also requires the non-installed role to expose the expected 140-triangle interior; the adapter is not a general arbitrary-garment loader test. The source inventory pins owned runtime sources, assets and package/Three metadata; it does not constitute a byte-for-byte archive of every transitive dependency implementation. Exact snapshot topology/byte binding still needs the separate archive verifier and numerical operator, and no historical replay, motion quality, mask correctness or asset promotion follows from this readiness verdict.
