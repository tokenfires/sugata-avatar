## 1. The entry point misstates which pages represent the current avatar

**Proven.** Baseline `packages/testbed/index.html:100–104` sends newcomers first to `alive`.
Baseline `packages/testbed/pages.js:127–129` says Converse is the only page building its figure
with `Avatar.create()`. The same baseline has actual calls in `src/portrait.js:55`,
`src/showcase.js:135` and `src/embed-example.html:101`. The exclusivity claim contradicts the
executable sources, not merely a style preference.

The catalogue also uses phase labels where the practical distinction is preview versus
measurement. `src/wardrobe.js:12–17` and `src/identity.js:17–20` explicitly describe diagnostic
rendering, and their executable setup uses simple lights. `src/post.js:125–126` defaults to
MSAA with grading off. A different-looking lab is therefore not by itself a renderer regression.
Whether this distinction caused a particular reported broken feature remains **inferred**.

- **Alternative A — recommend and implement:** lead with Portrait and Wardrobe studies, group
  the remaining pages by purpose, and give every destination a plain description, limitations,
  requirements and a separately dated review basis. This gives the user a current starting point
  while preserving reproducible instruments and all existing URLs.
- **Alternative B:** build one full application shell and migrate every lab beneath shared
  navigation, appearance controls and connection state. This would make transitions more cohesive,
  but shared scene or UI ownership can contaminate isolated measurement pages. It needs a distinct
  integration pass and is unnecessary to correct the proven catalogue contradiction.

**Implemented in this lane:** `index.html`, `pages.js`, and the existing catalogue gate. The
catalogue leads with two current previews, then connected conversation, focused labs, integration
checks, and reference/experiments. Phase-era claims and unverified numeric counts are removed.
Developer commands and evidence notes remain accessible in an expandable area. No diagnostic
renderer or scene was modified.

## 3. Speech wording hides the boundary between mouth animation and spoken audio

**Proven capability mismatch in naming.** `src/voice.html:81–83` presents “speak” and “start audio
clock”. `src/voice.js:176–188` creates/resumes an `AudioContext` and reads its clock; it does not
connect an audio source. `src/voice.js:81` explicitly identifies its timeline as synthetic.
Baseline `src/converse.js:366–383` supplies the same fixed 0.985-second mouth sequence, unrelated
to reply phonemes. `converse.html` does disclose synthetic timing, but that is different from a
plain statement that there is no spoken output or microphone connection.

The lack of connected audio is established by source. A user mistaking that silence for a broken
speaker is a **plausible interpretation, not a reproduced incident**.

- **Alternative A — recommend for the current coherence pass:** label the page “Mouth animation”,
  the action “Play mouth sequence”, and the clock control as timing only; disclose silent/text-only
  behaviour before interaction. Keep the synthetic sequence as a useful diagnostic. The catalogue and mouth-animation page now carry this distinction. The existing play/stop/clock
  DOM IDs and mechanics are preserved; the visible actions are “Preview mouth animation”,
  “Stop animation” and “Enable animation clock”.
- **Alternative B:** add a real speech adapter with audible output and engine-produced phoneme
  timing, then verify timing, interruption, pause/resume and audio disposal against actual speech.
  That is a substantive feature toward the brief, not a wording repair; a letter-derived or canned
  timeline cannot qualify it.
