# Base mesh verification — MPFB2 vs Anny vs MHR vs GNM

Verified 2026-08-06 by cloning all three repos, downloading MHR's 199 MB asset bundle and parsing
its FBX with a hand-written binary reader, installing and **executing** Anny to measure the gender
axis empirically, and downloading and inspecting MPFB2's `faceunits01` asset pack.

**This supersedes the character-source sections of [`character-assets.md`](character-assets.md) and
[`generative-3d-and-template-bases.md`](generative-3d-and-template-bases.md).**

## 🎯 Finding 1 — MPFB2 ships canonical ARKit-52 as CC0

**This reverses the earlier conclusion that MPFB2 has no blendshapes.** It does — they live in an
external asset pack rather than the repo, which is why the first research pass missed them.

`src/mpfb/services/faceservice.py:59` defines `ARKIT_FACEUNITS` as the exact Apple 52 in canonical
camelCase. The geometry ships in `faceunits01.zip` (258 KB, dated 2026-02-07, from
`files.makehumancommunity.org`):

```
packs/faceunits01.json
targets/faceunits/{52 files}.target   ← exactly 52, exactly the ARKit names
```

Per-target metadata:

```json
"cheekPuff": { "author": "Mika Suominen", "category": "Faceunit",
               "description": "Autogenerated ARKit faceunit",
               "license": "CC0", "type": "target" }
```

**Plus `MICROSOFT_VISEMES` (22, SSML) and `META_VISEMES` (15, OVR `viseme_aa … viseme_U`) — a
lip-sync path that ships in the box.**

🎯 **Mika Suominen is `met4citizen`, author of the MIT-licensed Three.js `TalkingHead` runtime.**
These shapes were built by someone shipping the exact browser stack we are targeting, and
TalkingHead's own CC0 demo avatar was produced by this same pipeline. **The chain is proven
end-to-end, not theoretical.**

Measured facial coverage (affected vertices per target):

| Target | Verts moved | Note |
|---|---|---|
| `jawOpen` | 2,543 | ⚠️ **pre-helper-removal.** Includes lower-teeth and tongue helper geometry that our pipeline deliberately deletes. **Post-bake the real figure is 2,239** — measured 2026-08-07. Do not cite 2,543 as a post-export constant. |
| `mouthClose` | 1,972 | **lip seal present** |
| `mouthPucker` | 1,729 | |
| `eyeBlinkLeft` | 783 | **eyelids present** |
| `browInnerUp` | 615 | |
| `tongueOut` | 226 | touches tongue helper |

Max vertex index 15,119 — indices into the full 19,158-vertex hm08 basemesh. **hm08-native, no
retargeting needed.**

Also bundled in-repo: **34 FACS-style expression units × 3 ethnicities**, CC0 — `eye-left-closure`,
`mouth-corner-puller`, `mouth-eversion`, `neck-platysma`, etc. The legacy MakeHuman AU set, useful
as a cross-check and correction source.

⚠️ **Quality flag:** the metadata literally says *"Autogenerated ARKit faceunit"* — almost certainly
transferred from another ARKit rig rather than hand-sculpted. **Budget an art pass** on
`mouthClose`, `mouthRollLower/Upper`, `eyeBlinkL/R` and the lid crease — exactly where automated
transfer usually breaks. Unverified: how well they hold at gender/age extremes, since they are
neutral-relative deltas applied independently of the macro shapes. **Needs a visual test.**

## ✅ Finding 2 — MPFB2 headless is a first-class supported path

**The highest-risk assumption in the plan is resolved.** MPFB2 requires Blender ≥ 4.2 and ships
`test/execute_tests_headless.bash` and `test/test_headless.py`. Standard
`blender --background --python script.py` invocation.

⚠️ Ergonomic wart: because Blender extensions land at unpredictable module paths, every script needs
a `dynamic_import()` shim — MPFB's own samples carry it verbatim.

## 🎯 Finding 3 — the gender axis is exactly linear

Measured by executing Anny:

```
mean |male − female| vertex displacement : 58.91 mm
mean |male − mid| = 29.4534109 mm ; |female − mid| = 29.4534114 mm
max |V(0.5) − ½(V(0)+V(1))| (rest)       : 2.2e-13 mm   ← exactly linear
```

**The androgynous midpoint is the exact arithmetic mean of the male and female bodies, to
floating-point precision.**

> **Design consequence:** the entire gender axis ships as **one morph target pair**.
> ```
> gender_masc = V(gender=1.0) − V(gender=0.5)
> gender_fem  = V(gender=0.0) − V(gender=0.5)
> ```
> Base mesh = the androgynous midpoint. A single slider reproduces every point on the axis
> *exactly*, and it composes additively with the 52 ARKit morphs. **The AI dials one float.**
> That is as cleanly as this requirement can possibly be met — and it confirms the design's
> choice to author expressions at the androgynous midpoint.

Anny's 11 semantic parameters, verified at runtime:
`gender, age, muscle, weight, height, proportions, cupsize, firmness, african, asian, caucasian`.
Default constructor trims to 6; pass `all_phenotypes=True` for all 11.

MPFB2 has the same macros — `macro.json` gives `gender` `low: female / high: male`, default 0.5.

Their own honest caveat, worth repeating: *"Phenotypes are based on preconceptions of artists …
they encode by design stereotypes of MakeHuman artists."*

## ⚠️ Finding 4 — the skeleton caveat that constrains the runtime design

**glTF cannot morph a skeleton.** Male↔female joint displacement, measured:

```
all bones, world                  : mean  89.4 mm   max 124.9 mm
head-region, world                : mean 109.5 mm   max 124.9 mm
head-region, re-rooted at 'head'  : mean  10.1 mm   max  17.5 mm
```

Even discounting global height, joints inside the head shift up to **~17.5 mm across the full
sweep (≈ ±9 mm from the androgynous midpoint)**. Runtime morph-target gender on a fixed bind
skeleton introduces visible skinning error at the extremes — jaw pivot and eye placement drift
about a centimetre.

**Mitigations, in order of honesty:**
1. **Bake gender at build time and ship 3–5 discrete GLBs.** The honest option if photoreal is the goal.
2. Clamp the runtime axis to a narrower band around the midpoint.
3. Drive the jaw/eye bone rest transforms from the same scalar in JS alongside the morph.

**Our plan: ship discrete baked GLBs as the default, with the continuous morph pair available as a
live-preview mode within a clamped band.** Best of both — exact quality at the shipping points, a
real-time dial for the AI to explore its own identity.

## Finding 5 — why MHR loses, despite being the best-engineered

Apache-2.0 with zero ambiguity (asset bundle LICENSE is byte-identical to the repo's, MD5 verified),
7 LODs with UVs, 126-bone rig, neural pose correctives, real CPU inference. And it fails both
deciding requirements:

🚩 **No gender parameter.** `grep -io "gender\|female\|male\|sex\b" assets/compact_v6_1.model`
returns **nothing**. The identity space is 45 unnamed PCA coefficients. Getting a gender dial means
*discovering* the direction — a research task with no labelled data and no guarantee it
disentangles from height/weight/muscle. MHR's 68 named parameters are *skeleton scales*
(`scale_hip_width`, `scale_shoulder_width`), not soft-tissue identity.

🚩 **117 blendshapes, all unnamed.** FBX parsing gives `shape_0 … shape_116` / `shape_c_0 …
shape_c_116` — 45 identity + 72 expression, confirmed by affected-vertex counts. No ARKit names, no
published mapping, and **no eyelid, lip or brow bones** to fall back on (the skeleton has `c_jaw`,
`c_teeth`, `c_tongue0..4`, `l_eye`, `r_eye` only). All 52 ARKit shapes would be authored from
scratch — **on an all-triangle mesh with no edge loops**, which is the hard way to sculpt eyelids
and lip seal.

Also: **4.77 GB unpacked** (one file is 2.65 GB), and **no exporter of any kind** — you get
`torch.Tensor`.

SMPL taint: **none in the core path.** SMPL appears only in `tools/mhr_smpl_conversion/`, which
requires you to supply your own model files. The bundled correspondence files contain indices and
barycentric weights only. Delete `tools/` and MHR is unambiguously clean.

## Finding 6 — GNM Head is the upgrade path, not the starting point

Google's **GNM Head** (Apache-2.0, released 2026-07-28, arXiv 2607.23687). Head-only, no body, no
gender parameter (only a `Gender` IntEnum conditioning a CVAE sampler), no ARKit.

But: **quad topology with UVs**, separately modelled eyeballs / teeth / gums / tongue, 46
anatomically named vertex groups, and a **383-dimension regionally-localised expression basis**
(`left_eye_region_000..099`, `lower_face_region_000..149`, `tongue_000..030`, `pupils`).

> **If photoreal close-up portrait turns out to be the binding constraint rather than the gender
> axis, revisit this.** Fit ARKit-52 into its 383-dim regional basis by least squares, and
> synthesise a gender axis from the `IdentitySampler` class-conditional means. Real work, but the
> ceiling is materially higher than hm08's — which is a 2010s mesh.

## Topology detail

```
MPFB2 base.obj  : 19,158 verts | 18,486 quads | 21,334 UVs | 144 named vertex groups
after helper removal : 13,718 verts | 13,710 quads   ← identical counts to Anny
```

hm08 is a hand-modelled quad cage with proper radial loops around eyes and mouth, built for
animation and subdivision. **13 alternative UV layouts ship** — `eyelids_horizontal_split`,
`lips_horizontal_split`, `eyes_wide_cross_split`, `face_solid`, `scalp_solid` — exactly what a
close-up face needs for texel density on lips and lids.

⚠️ **Diff the index maps before assuming faceunits transfer between Anny and MPFB2 without
remapping.** Both derive from the same 19,158 base and both report 13,718 post-removal, but the
orderings were not verified identical.

## Licence reading

MPFB2's `LICENSE.md` §D is explicit and resolves the GPL question in our favour:

> *"It is the opinion of the MakeHuman team that no output from MPFB contains any trace of program
> logic … regardless of whether you use the UI as such or if you call functions of MPFB via a
> script … As the assets have been released under CC0, there is no limitation on what you can do
> with this combined output."* — explicitly naming exports to FBX, OBJ, DAE, MHX2 and *"graphical
> data generated via scripting or plugins."*

**Practical reading: our exported GLB is CC0-clean and freely distributable. What we may not do is
link MPFB2's Python into a non-GPL product — so MPFB2 is build-time only and can never be part of
the shipped runtime.** That matches our offline/runtime split exactly.

## The build pipeline

1. **Build-time, headless Blender 4.2+:** MPFB2 → set `gender` ∈ {0.0, 0.25, 0.5, 0.75, 1.0} →
   `FaceService.load_targets(basemesh, load_arkit_faceunits=True, load_meta_visemes=True)` →
   `ExportService.bake_modifiers_remove_helpers(...)` → `bpy.ops.export_scene.gltf(...)`.
   Ships GLBs each with 52 correctly-named ARKit morphs + 15 OVR visemes, UVs, and a
   `game_engine` or `mixamo` skeleton.
   `ExportService._apply_modifiers_keep_shapekeys` preserves shape keys through modifier baking —
   the usual failure mode, already handled.
2. **Continuous dial:** generate the ± gender morph pair from Anny, add as an extra morph target.
3. **Runtime:** Blender's glTF exporter maps shape keys → glTF morph targets, so **the 52 ARKit
   shapes survive export by name.** `met4citizen/TalkingHead` (MIT) already drives exactly this
   morph namespace in three.js.
4. **Art pass:** `mouthClose`, `mouthRollLower/Upper`, `eyeBlinkL/R`, lid crease — cross-checked
   against the in-repo CC0 FACS units. **That is the difference between "works" and "photoreal."**

## Bugs and warts found

- 🐛 **Anny v0.5: `pip install anny` is broken.** `models/__init__.py:25` unconditionally imports
  `anny.models.soma` → `warp`, which is an *optional* extra. **Always install `anny[warp]`.**
- ⚠️ Anny's `pyproject.toml` declares `license-files = [..., "LICENSE_THINGS"]`, which doesn't exist.
- ⚠️ MPFB2's `dynamic_import()` shim is required in every headless script.
