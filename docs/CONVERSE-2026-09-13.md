# Converse and testbed recovery — September 13, 2026

The testbed now starts with the current Portrait and Wardrobe studies, and describes every other
page by purpose, requirements and remaining limitations. The old phase labels and contradictory
claim that Converse alone uses Avatar.create are removed. All 17 destinations remain available,
with the hub making 18 build entries. Dated source review is separate from browser evidence.

## Converse's current behavior

The default Converse view uses the accepted g050 Everyday outfit and chin bob, through the same
preset module as the lookbook. This is reuse of the accepted assets, not a new hair or clothing
quality claim. Other explicitly requested body studies retain their existing custom-figure path.
The page has a readable transcript, mobile layout, testbed/portrait/lookbook navigation and
collapsible expression/rendering details.

Opening Converse reads the local model list only. It never silently substitutes a model or
starts inference. An absent URL-selected model is named in an actionable message. The user selects
an exact advertised chat-model ID and clicks Connect, which may cause LM Studio to load that model.
The list does not establish residency or chat compatibility. Empty/unavailable/malformed lists,
connection failures and reply failures have refresh/retry paths. Switching models explicitly
starts a new conversation; the old visible transcript remains separated by a new-model notice.

Connect warms the existing two request schemas, checks the reply result, and labels model expression
interpretation experimental. The historical affect warm-up only checks transport; it does not
certify semantic expression output. Each real turn retains the existing order: immediate local
text estimate, reply, Avatar.say, then validated model appraisal. A rejected appraisal retains the
local response and shows a degraded-expression explanation. A successful retry replaces stale
failure status. Controls prevent concurrent setup/turns. Leaving the page aborts requests,
stops its optional own-clock driver and retires the Avatar.

Voice and microphone are not connected. The optional canned mouth sequence is off by default and
is explicitly a sample animation, unrelated to the reply's phonemes. The separate voice diagnostic
now says Mouth animation / Preview mouth animation / Enable animation clock, preserving its
existing mechanics and element IDs.

## Evidence and limits

`captures/converse-resume-2026-09-13/` contains the browser reports, before/after screenshots and
independent critic probe. The baseline loaded the real WebGPU page and real local model list,
but intercepted completion requests: it tried the absent historical model twice, received the
controlled missing-model response, and left Send enabled. This reproduces the page's response to
that failure, not a real generation attempt against the absent model. Actual local discovery
still advertised seven models on September 13; none was automatically selected or loaded.

The first repaired browser pass passed 14 groups. Independent review found a stale retry message
and a warm-up readiness overclaim; both were corrected. The reviewed pass adds actual own-clock
page retirement and successful retry without reconnect. One intermediate run stopped on a test
readiness typo (an unbound global before page boot); its report remains under `reviewed/`.
The corrected run is `reviewed-v2/` and passed 16 groups with live read-only model discovery.

The final fixture-only run is `final/browser-report.json`: **17 browser groups passed, zero unexpected JavaScript/GPU errors**. It also exercises malformed affect after
HTTP-successful warm-up. All model completions are controlled fixtures, while Avatar, WebGPU,
clothing, hair and page controls are real. This proves the connection/recovery and expression
plumbing under the tested responses, not live model quality, latency, universal compatibility,
all body configurations, AAA appearance, speech audio or lip-sync accuracy.
