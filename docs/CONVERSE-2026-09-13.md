## Converse's current behavior

The default Converse view uses the accepted g050 Everyday outfit and chin bob, through the same
preset module as the lookbook. This is reuse of the accepted assets, not a new hair or clothing
quality claim. Other explicitly requested body studies retain their existing custom-figure path.
The page has a readable transcript, mobile layout, testbed/portrait/lookbook navigation and
collapsible expression/rendering details.

Opening Converse reads the local model list only. It never silently substitutes a model or
starts inference. An absent URL-selected model is named in an actionable message. The user selects
an exact advertised chat-model ID and clicks Connect, which may cause LM Studio to load that model.
The list does not establish residency or chat compatibility. Empty/unavailable/malformed lists,
connection failures and reply failures have refresh/retry paths. Switching models explicitly
starts a new conversation; the old visible transcript remains separated by a new-model notice.

Connect warms the existing two request schemas, checks the reply result, and labels model expression
interpretation experimental. The historical affect warm-up only checks transport; it does not
certify semantic expression output. Each real turn retains the existing order: immediate local
text estimate, reply, Avatar.say, then validated model appraisal. A rejected appraisal retains the
local response and shows a degraded-expression explanation. A successful retry replaces stale
failure status. Controls prevent concurrent setup/turns. Leaving the page aborts requests,
stops its optional own-clock driver and retires the Avatar.

Voice and microphone are not connected. The optional canned mouth sequence is off by default and
is explicitly a sample animation, unrelated to the reply's phonemes. The separate voice diagnostic
now says Mouth animation / Preview mouth animation / Enable animation clock, preserving its
existing mechanics and element IDs.

## Verified installed model — 08:25 PDT

Rob reported that several models failed the structured-reply check and explicitly requested a
working installed model or a download recommendation. Real local inference and one additional
already-downloaded model load were used for this investigation; the earlier fixture-only results
below remain distinct.

**Use `qwen3-4b-instruct-2507-mlx`: choose it in Converse and click Connect.** It was already
downloaded. It was loaded with an 8,192-token context, one concurrent prediction, and a one-hour
idle expiry; no download, runtime update, global thinking-setting change, or replacement of the two
previously loaded models was required. LM Studio was `0.4.24+1`, with the selected native MLX
runtime `1.11.0`. The [Qwen model card](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507)
describes this family as non-thinking; the actual local test, not that description alone, is the
compatibility evidence.

The unchanged real WebGPU Converse page connected and completed **six synthetic turns** with
both replies and accepted tier-2 appraisals. All 14 real API responses (two warm-ups and twelve
turn requests) returned HTTP 200 and `finish_reason: stop`, with JSON in `content`. No completion
was intercepted and the production four-second per-request deadlines were unchanged. Replies took
2.96–3.27 seconds; appraisals 0.99–1.85 seconds; whole turns 3.95–4.93 seconds. The first direct
4B reply before warm-up took 13.14 seconds: Connect remains necessary.

Compatibility is not expression calibration. The nervous-presentation test was interpreted as
low-arousal annoyance, despite passing validation. Six prompts do not establish general reliability,
conversation quality, or human-level emotional understanding. The source and model runtime must be
rechecked after changes.
